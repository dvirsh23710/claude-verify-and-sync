# verify-and-sync: בדיקה, שמירה וסנכרון (Skill ל־Claude Code)

**[English →](README.md)**

**די לעבור בעצמך על כל המסכים אחרי כל שינוי של ה־AI.** אחרי כל תיקון או פיצ׳ר, ה־Skill הזה גורם ל־Claude **להוכיח** שהשינוי עובד, ואז לשמור ולסנכרן אותו:

1. **רושם מה ביקשת:** כל בקשה נרשמת יחד עם בדיקה ברורה שמוכיחה אותה. למשל: "כמנהל, בעמוד הדוחות, הסיכום שווה לסכום השורות".
2. **מריץ את כל הבדיקות האוטומטיות:** בדיקת טיפוסים ואיכות קוד, פורמט, בדיקות יחידה ואינטגרציה, בדיקות מסד נתונים, בניית גרסת ייצור ובדיקות מקצה לקצה.
3. **עושה סיור מסכים:** נכנס **כל סוג משתמש** ופותח **כל מסך**. בכל מסך הוא בודק:
   - את הבקשות שלך (טקסט שחייב להופיע, או שאסור שיופיע);
   - שגיאות בדפדפן;
   - גלילה הצידה בטלפון;
   - בעיות נגישות חמורות.

   כל מסך מצולם ל**עמוד גלריה אחד**, ובראשו הבקשות שלך עם ✅ או ❌.
4. **שומר ומסנכרן:**
   - שומר קומיט ומעלה ל־GitHub;
   - מקדם את `main` **רק אם הבדיקה המלאה עברה על בדיוק אותו קוד**;
   - מעדכן worktrees נוספים, למשל סוכן AI שני, כשהם לא באמצע עבודה;
   - כותב מחדש את קובץ המצב `docs/HANDOFF.md`: "איפה אנחנו עומדים".
5. **מדווח במילים פשוטות,** בעברית או באנגלית: שורה לכל בקשה, עם הגלריה.

ה־Skill נבנה לבעל מוצר לא טכני, שבזבז שעות על בדיקה חוזרת של כל המסכים אחרי כל שינוי של ה־AI. עכשיו הוא עובר על עמוד אחד.

**ב־Claude.ai או באפליקציה:** מורידים את [`dist/verify-and-sync.skill`](dist/verify-and-sync.skill) ומוסיפים אותו ב־*Settings → Capabilities → Skills*. הסקריפטים רצים בתוך הפרויקט שלך, ולכן היתרון האמיתי שלו הוא ב־Claude Code.

**ידנית:** מעתיקים את התיקייה `plugins/verify-and-sync/skills/verify-and-sync/` אל `.claude/skills/` בפרויקט.

## שימוש ראשון

פותחים את הפרויקט ב־Claude Code ואומרים: **"תתקין את verify-and-sync בפרויקט הזה"**. Claude יעשה את הדברים הבאים:
- יעתיק את הסקריפטים לפרויקט;
- יכתוב קובץ הגדרות (`verify.config.json`) שמתאים לפקודות האמיתיות שלך;
- יבנה את סיור המסכים (`tests/tour/stops.ts`: התפקידים והמסכים שלך);
- ייצור את קובץ הבקשות ואת קובץ המצב;
- יריץ הכול פעם אחת.

מאותו רגע זה קורה לבד בכל פעם ש־Claude מסיים שינוי. אפשר גם פשוט לבקש: "תבדוק שהכל עובד" או "תשמור ותסנכרן".

## מה צריך

- **חובה:** מאגר git ו־Node.js 18 ומעלה.
- **לסיור המסכים:** אפליקציית אינטרנט עם בדיקות [Playwright](https://playwright.dev) ששומרות התחברות (`storageState`) לכל תפקיד.
- **רשות:** `@axe-core/playwright` לבדיקת הנגישות.

## בטיחות מובנית

- **`main` מתקדם רק על קוד שנבדק.** הסנכרון משווה "טביעת אצבע" של הקבצים שנבדקו למה שנשמר בקומיט, ורק מסמכים מותר שיהיו שונים.
- **בדיקה אחת בכל רגע** לכל מאגר, באמצעות מנעול משותף. סוכנים שעובדים במקביל לא מתנגשים במסד הנתונים.
- **נתוני הדמו לא מאופסים** כשמישהו אחר באמצע עבודה, או אחרי כישלון, כדי שהראיות יישארו.
- **אין דריסה בכוח** (force push). ענפים שהתפצלו מדווחים, ולא נדרסים.
- **בדיקות לא נחלשות כדי שהכול ייצא ירוק:** מתקנים את המוצר, או מעדכנים את הבדיקה ומציינים איזו החלטה שינתה אותה.
